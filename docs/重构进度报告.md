## 八、缺陷修复（独立于 M0–M8 路线图）

### 客户端本地数据「跨服务器串档」修复

- **现象**：不同服务器（各自独立 SQLite）切换后，客户端本地 IndexedDB 缓存库名（`gipfel-client-cache-u<id>`）与 token 键（`acct_u<id>__token`）只按用户 id 命名、不含服务器地址；而 seed 在每台服务器都造出相同 `admin`（id=1）。当两台服务器 `JWT_SECRET` 相同时，admin 会话无感横跨两台服务器、数据写回同一个本地桶 → 串档。
- **根因**：本地命名空间只做到「账号级」，没做到「服务器级」。
- **修复**：
  - 新增 `utils/realm.ts`：对归一化服务器地址做确定性短哈希作为 `realm`；
  - 缓存库名升级为 `gipfel-client-cache-<realm>-u<id>`、账号键前缀升级为 `acct_<realm>_u<id>__`；
  - `config/index.ts` 新增集中式 `setServerUrl`：切换服务器时清理旧 realm 的 token + IndexedDB、重置登录态、清空内存 memo，从根杜绝跨服冒用；
  - 升级兼容：`migrateOldAccountKeys` 把旧 `acct_u<id>__` 键 re-key 到当前 realm，已登录用户无缝保留登录态；`deleteOldAccountDbs` 清理旧格式 IndexedDB。
- **验证**：`vue-tsc --noEmit` 零错误。
