# 股票系统优化设计（消除一字涨停/跌停）

> 版本：v2（定稿）
> 状态：决策已确认 ✅（A1–A5 全部按推荐确认，待实施）
> 关联代码基线：`server/src/modules/stock/engine.ts`、`server/src/modules/stock/stock.service.ts`、`server/src/modules/stock/dto/stock.dto.ts`、`client/src/views/stocks/StockManageView.vue`
> 阅读对象：本系统维护者。本文档只讨论「为什么股票总是一字涨停/跌停，以及如何让价格围绕真实供需正常波动」这一件事；权限、数据同步等其余领域不涉及。

---

## 1. 背景与目标

用户反馈：**「现在的股票总是一直涨停或者一直跌停」**。排查后确认现象真实存在，且不是偶发——当比赛运营设置的幸福度 / 碳排字段偏离基准、或玩家单边下单时，股票价格会稳定地封在 ±10% 涨停/跌停板上，甚至出现「涨停→涨停→跌停→跌停→涨停」的锯齿振荡，市场完全失真。

本次优化目标：

1. **消除一字板**：价格围绕真实供需波动，涨跌停只作为极端行情的安全边界，而非常态；
2. **因子解耦**：幸福度 / 碳排不再直接放大涨跌幅，买卖均衡时价格保持稳定；
3. **做市商增强**：流动性供给与总股本规模匹配，深度动态化；
4. **干预机制重设计**：连续涨跌停干预从「砸盘/托市」改为「温和回归」，消除锯齿振荡；
5. **成交价参与定价**：价格发现与真实成交挂钩，零成交不动价；
6. **全参数可配置**：涨跌幅、波动基准、做市商深度、干预模式等全部可配置，默认值经调优。

## 2. 现状：定价与撮合链路全景

### 2.1 核心公式（`engine.ts`）

**撮合 `computeMatch`（`engine.ts:31-47`）**：

```
最高买价 = MAX(全部买单价格)；最低卖价 = MIN(全部卖单价格)
成交价   = (最高买 + 最低卖) / 2
是否成交 = 最高买 >= 最低卖
```

**定价 `computePrice`（`engine.ts:65-89`）**：

```
幸福因子 = 1 + 0.2 × (幸福度 - 50) / 50          // 范围 [0.8, 1.2]
碳因子   = 1 - 0.5 × (当前碳排 - 行业均值) / 行业均值  // 可到 1.25+
买卖压力比 ratio = 买盘总额 / 卖盘总额
    无卖单且有买单 → Infinity；无买单且有卖单 → 0；无单 → 1
理论价 = 上轮收盘 × ratio × 幸福因子 × 碳因子
最终价 = 限幅(理论价, 上轮收盘×0.9, 上轮收盘×1.1)   // ±10% 硬限幅
```

**K 线 `buildCandle`（`engine.ts:123-150`）**：开盘=上轮收盘，收盘=最终价，影线在实体/理论价外叠加确定性盘中波动，全部限幅在 ±10% 内。

**初始价 `computeInitPrice`（`engine.ts:153-160`）**：

```
ROUND(initNetProfit × 10000 / totalShares / industryPE, 2)
// initNetProfit 单位「万」，totalShares 单位「万股」，industryPE 为 PE 倍数
```

### 2.2 推进轮次流程（`stock.service.ts:985-1188`）

`advanceRound`（仅 `stock:manage` 高级管理可调）对每只股票依次执行：

```
1. applyPbRound(stock)            // PE 联动刷新 / 随机 ±2 游走，重算初始价
2. generateMarketMakerOrders()    // AI 做市商挂单（撮合前）
3. advanceOneStock()              // 撮合 → 定价 → 资金划转 → 订单状态 → K 线 → 更新股价
```

### 2.3 做市商挂单（`stock.service.ts:775-983`）

每轮推进、撮合前自动挂单（默认 `enabled=true, spreadPct=2%, levels=3, baseQuantity=1000`）：

- **建仓单**：持仓不足时以当前价买入补齐（并直接写入持仓 + 扣现金）；
- **常规盘**：以当前价为基准，卖单挂 `+2%/+4%/+6%`（量 1000/2000/3000 股），买单挂 `-2%/-4%/-6%`（金额与卖单对称）；
- **连续涨跌停干预**（`stock.service.ts:883-940`）：
  - 最近 3 根 K 线中**连续涨停 ≥ 2 轮** → 在 `当前价×1.05` 与 `当前价×1.1` 各挂 **10000 股**大卖单（`interventionQty = baseQuantity × 10`）；
  - 连续跌停 ≥ 2 轮 → 在 `当前价×0.95` 与 `当前价×0.9` 各挂 10000 股大买单；
- **旧单清理**：挂新单前把做市商上轮未成交 PENDING 单全部置为 CANCELLED（`stock.service.ts:829-832`）。

### 2.4 撮合与定价（`advanceOneStock`，`stock.service.ts:1018-1188`）

- 取该股票全部 PENDING 订单（含做市商单）→ `computeMatch` 得成交价 → `computePrice` 得最终价（**两者互不依赖**）；
- 撮合循环：买价降序、卖价升序，`buy.price >= sell.price` 才成交，按 `tradePrice` 划转资金/持仓；
- 订单状态：全成交 → FILLED；部分成交 → 更新剩余数量保持 PENDING；未成交保持 PENDING；
- 无论是否真实成交，只要存在订单，最终价都会写入 `currentPrice` 并生成 K 线（`stock.service.ts:1125-1178`）；
- **连续涨跌停干预只影响做市商挂单，不直接干预定价公式**。

### 2.5 客户端

- `StockManageView.vue:232-261`：推进轮次对话框可配置做市商（启用/点差/档数/基准量）；
- `StockManageView.vue:707`：推进时把 `mmConfig` 随 `advance-round` 请求提交。

## 3. 问题清单（P 系列）

### P1（致命）幸福因子 / 碳因子直接放大涨跌幅 → 均衡盘也封板

`computePrice` 中两个因子**直接乘在理论价上**，与买卖压力完全解耦：

- 幸福因子 = `1 + 0.2×(happiness-50)/50`：`happiness=75` → 1.10；`happiness=100` → 1.20；
- 碳因子 = `1 - 0.5×(currentCarbon-avg)/avg`：碳排为均值一半时 → 1.25。

**关键事实**：即使买卖完全均衡（`ratio=1`），只要幸福度 ≥ 75 或碳排显著低于均值，理论价 = 上轮收盘 × 1.10+ → 直接封涨停；反之封跌停。**比赛运营者把幸福度/碳排字段设得偏离基准，全体股票就会无条件朝一个方向封板，与交易行为无关。** 这是「总是一直涨停/跌停」最隐蔽、最根本的来源。

### P2（致命）定价公式 = 金额比，单边即封板

`ratio = 买盘总额 / 卖盘总额`：

- 无卖单且有买单 → `Infinity` → 直接封涨停；
- 无买单且有卖单 → `0` → 直接封跌停；
- 即使双边都有单，只要一边金额显著占优（如玩家集体买入），ratio 会远大于 1，理论价直接顶到 ±10% 限幅。

金额比没有「净买压饱和」概念——不存在中间态，供需轻微失衡就顶板。

### P3（高）做市商流动性深度固定且与股本脱节

- `baseQuantity=1000` 是**固定股数**，与股票总股本（`totalShares` 单位是**万股**）完全脱节：总股本 100 万股与 10 亿股的股票，做市商每轮都只供 6000 股；
- 常规盘单边金额 ≈ `6280 × 股价`。玩家单边买入 1 万股（金额 ≈ 11000 × 股价），买盘金额已超卖盘 → 封涨停；
- 结果：做市商只保证「有对手盘」，无法吸收真实单边压力，**流动性深度严重不足**。

### P4（高）连续涨跌停干预设计缺陷 → 锯齿振荡

干预逻辑（`stock.service.ts:883-940`）存在三个叠加缺陷：

1. **力度过猛、反向封板**：干预挂单量 = `baseQuantity × 10 = 10000 股/档 × 2 档 = 20000 股`，是常规盘（6000 股）的 3 倍以上。干预一旦触发，卖盘金额骤增数倍，`ratio` 从 ≫1 直接跌到 ≪1 → **当轮直接跌停**；
2. **干预价锚在涨停后的高价**：`当前价×1.05 / ×1.1` 是「已涨上来的价」，不是「回归价」——干预单只能吸收买压，不能引导价格回落到均衡；
3. **干预后计数清零 → 无法连续回归**：干预当轮若未封板（`changePct` 非 ±9.9%），连续计数被清 0，下一轮又回到无干预状态继续封板。**实际轨迹：涨停→涨停→干预→跌停→跌停→干预→涨停……锯齿振荡**，用户感知即「总是一直涨停或者一直跌停」。

### P5（高）成交价（tradePrice）不参与定价 → 价格发现失真

- `computeMatch` 的成交价只用于资金/持仓划转，`computePrice` 用金额比独立定价；
- 即使撮合在 `1.06×上轮收盘` 大量成交，定价公式仍可能算出涨停价——**价格信号与真实成交脱节**，K 线收盘价不代表市场实际成交水平。

### P6（中）零成交也动价

- `advanceOneStock` 只在 `orders.length === 0` 时跳过（`stock.service.ts:1025`）；只要存在订单（哪怕 `matched=false`、一轮零成交），`computePrice` 依然算出新价并写入 `currentPrice` + 生成 K 线；
- 玩家挂「涨停价买单 + 跌停价卖单」（最高买 < 最低卖，不成交）时，价格仍会因金额比变化而乱跳。

### P7（低）初始价量纲与边界校验缺失

- `computeInitPrice` 在 `industryPE <= 0 || totalShares <= 0` 时返回 **0**（`engine.ts:158`），若创建时未校验，股票初始价为 0，`computePrice` 中 `lastClose=0` 导致 `upper=lower=0`、价格永远为 0；
- 量纲为 Excel 原始公式（`净利润(万)×10000/股本(万股)/PE`），与「PE × 每股净利」的常规估值口径不一致，可能导致初始价绝对值异常（过高/过低），进而放大后续涨跌。

## 4. 优化方案（S 系列）

### S1：定价公式重设计 ——「净买压力 + 压缩比例」替代裸金额比（✅ A1 已确认）

**目标**：P1/P2。让价格对供需失衡有「连续响应」，单边行情不再直接顶板。

**方案（推荐）**：

```
净买量     netQty    = 买单总量 - 卖单总量（股）
压力系数   pressure  = netQty / (买单总量 + 卖单总量 + 1)        // ∈ [-1, 1]，防除零
方向漂移   drift     = 0.2 × (幸福度 - 50) / 50                  // 只作长期趋势偏置，见 S3
理论价     theoretical = 上轮收盘 × (1 + pressure × maxMovePct + drift × maxMovePct)
最终价     final     = 限幅(理论价, 上轮收盘×(1-limitPct), 上轮收盘×(1+limitPct))
```

- `maxMovePct`（默认 5%）：单轮价格相对买卖压力的**最大移动幅度**。单边行情理论最大 ±5%，不再直接顶 ±10% 板；
- `limitPct`（默认 10%）：仍保留涨跌停硬边界，但只在极端行情（叠加多轮漂移）时触及；
- **效果**：买卖均衡 → pressure≈0 → 价格基本持平；单边大单 → 最多 ±5% 温和波动，给下一轮做市商和反向单留出反应空间。

> 备选方案（若希望保留金额比语义）：`ratio' = (buyAmount + ε) / (sellAmount + ε)`，`theoretical = lastClose × (ratio')^γ`，γ 为压缩指数（默认 0.5）。两者都消除了「Infinity 直接封板」，但净买压力方案更直观、更易调参，**推荐净买压力方案**。

### S2：因子解耦 —— 幸福度 / 碳排改为「趋势偏置」，不放大单轮涨跌（✅ A2 已确认）

**目标**：P1。消除「均衡盘也封板」的系统性推涨/推跌。

**方案**：

- 幸福度、碳排**不再乘在理论价上**，而是压缩后作为压力偏置（`drift`，见 S1 公式），单轮影响上限收敛到 `±0.2 × maxMovePct`（即 ±1% 左右）；
- 碳排因子改为**相对偏离的软映射**：`carbonDrift = 0.2 × clamp((avg - currentCarbon) / avg, -1, 1)`（碳排低 → 轻微正偏置，碳排高 → 轻微负偏置），不再出现 1.25 倍的直接放大；
- **效果**：买卖均衡时价格保持稳定（drift ≤ ±1%），幸福度/碳排只引导长期趋势，不制造一字板。

### S3：做市商流动性动态化 —— 深度与股本挂钩

**目标**：P3。让做市商供给匹配市场真实规模。

**方案**：

```
depthPct 默认 0.1%（可配）
baseQuantity = clamp(round(totalShares × 10000 × depthPct), mmMinQty=1000, mmMaxQty=100000)
```

- 总股本 1 亿股 → `baseQuantity = 10000 股/档`（常规盘 3 档单边 6 万股）；
- 点差可随波动率自适应：最近 3 轮波动大 → `spreadPct` 自动加宽（默认 `2% + 3×波动率`），波动收敛后回落；
- 建仓单、干预单的基准量同步使用动态 `baseQuantity`。

### S4：连续涨跌停干预重设计 ——「温和回归锚」替代「砸盘/托市」（✅ A3/A4 已确认）

**目标**：P4。消除锯齿振荡，让干预真正把价格拉回均衡。

**方案（推荐：回归锚模式）**：

```
触发条件：最近 3 根 K 线连续封板 ≥ 2 轮（保留）
干预方向：与封板方向相反（涨停→卖压、跌停→买压）
干预价格：锚在「上轮收盘 × (1 ± regressionPct)」，regressionPct 默认 2%（而非当前价的 ±5%/±10%）
干预数量：吸收真实净压——取最近 3 轮玩家净买入量的移动平均（而非固定 10000 股）
观察窗口：干预触发后 2 轮内即使未封板也不清零连续计数；窗口结束后按实际 K 线重新计数
```

- 干预价 = 回归锚而非砸盘价：涨停后干预卖单挂在 +2% 处，玩家买盘被吸收后价格自然回落到 +2% 以内，**不会反向封跌停**；
- 干预量 = 真实净压的移动平均：只吸收「多余」的买压，不制造反向卖压；
- 观察窗口：避免「干预一轮 → 计数清零 → 下轮再封板」的振荡。

> 备选方案：**扩板模式**——连续封板 ≥ 2 轮时，本轮 `limitPct` 自动放宽（10% → 15% → 20%），让市场在更大空间内自行消化压力，不做市商干预。两种模式可配置切换（`interventionMode: "regression" | "expand-limit"`），**推荐回归锚模式**（对玩家体验更平滑）。

### S5：成交价参与定价 —— 价格锚定真实成交

**目标**：P5。价格发现与成交挂钩。

**方案**：

- 当 `matched=true` 且 `tradePrice` 有效时：`final = 限幅(0.7 × tradePrice + 0.3 × theoretical, 上轮收盘×(1±limitPct))`（权重可配）；
- `matched=false`（零成交）时：不采用金额比定价，`final = 上轮收盘`（平盘），并生成平盘 K 线或跳过本轮；
- **效果**：K 线收盘价反映真实成交水平，市场信号可信。

### S6：零成交不动价

**目标**：P6。

- `orders.length === 0` 或 `matched === false` → `currentPrice` 不变，不生成 K 线（返回 `{ skipped: true }`）；
- 杜绝「挂单不成交、价格乱跳」。

### S7：创建校验与初始价边界

**目标**：P7。

- `createStock` 校验：`totalShares > 0`、`initNetProfit > 0`、有效 `industryPE > 0`（联动/随机模式下取计算后的值）；
- 初始价合理性警告：`computeInitPrice` 结果 ≤ 0 或 > 10000 时拒绝创建并提示检查净利润/股本/PE 量纲。

### S8：参数配置化（比赛级 `stockConfig`）（✅ A3 可配已确认）

**目标**：全部魔法数字可配置。新增 `Competition.stockConfig`（JSON，默认值见下表），推进轮次对话框与股票管理页可编辑：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `limitPct` | 0.10 | 涨跌停限幅（±10%） |
| `maxMovePct` | 0.05 | 单轮价格最大移动（相对买卖压力） |
| `happinessImpact` | 0.2 | 幸福度趋势偏置强度 |
| `carbonImpact` | 0.2 | 碳排趋势偏置强度 |
| `mmDepthPct` | 0.001 | 做市商单档深度占总股本比例 |
| `mmMinQty` / `mmMaxQty` | 1000 / 100000 | 单档深度下限/上限（股） |
| `mmSpreadPct` | 0.02 | 做市商基准点差 |
| `interventionMode` | `"regression"` | `regression`（回归锚）/ `expand-limit`（扩板） |
| `regressionPct` | 0.02 | 回归锚干预价格偏移 |
| `tradePriceWeight` | 0.7 | 最终价中成交价的权重 |

### S9：可观测性 —— 每轮记录定价诊断

- `advanceOneStock` 返回值附带诊断字段：`{ pressure, drift, theoretical, final, matched, tradePrice, mmIntervened, buyQty, sellQty, buyAmount, sellAmount }`；
- `stock:round-advanced` 实时事件携带汇总诊断，前端 K 线图旁可展开「定价诊断」面板，运营可直接看到**为什么本轮涨/跌/封板**；
- 便于调参与排障（例如一眼看出幸福度偏置导致全市场推涨）。

## 7. 验收标准

1. **均衡盘持平**：买卖金额相等的市场，价格单轮波动 ≤ ±1%，不再因幸福度/碳排封板；
2. **单边温和波动**：玩家单边买入 1 万股，单轮最大涨幅 ≤ maxMovePct（默认 5%），不再直接封 ±10% 板；
3. **无锯齿振荡**：连续 5 轮推进，不出现「涨停↔跌停」交替轨迹；干预轮价格回落幅度温和（≤ ±3%）；
4. **零成交不动价**：无订单或撮合不成交时，`currentPrice` 保持不变；
5. **成交价可信**：有成交时 K 线收盘价与 `tradePrice` 偏差 ≤ 30%（权重 0.7 时）；
6. **全参数可配**：`stockConfig` 生效，修改后推进行为随之变化；
7. **可观测**：每轮推进返回诊断字段，前端可查看定价依据。

---

## 8. 风险与回退

- **风险**：新定价公式改变市场节奏，玩家「低价买入等涨」的策略收益下降——属预期行为（市场更真实），可通过 `maxMovePct` 上调（如 8%）调节；
- **风险**：做市商深度与股本挂钩后，大股本股票每轮成交额增大，需确认做市商账户现金（初始 10 亿）充足——必要时随 `stockConfig` 提供 `mmInitialCash` 配置；
- **回退**：所有新参数均有默认值且 `stockConfig` 可整体关闭（`enabled=false` 时回退旧公式）；`engine.ts` 保持纯函数，单测覆盖新旧公式边界。

```
「总是一直涨停/跌停」根因链
├─ P1 幸福/碳因子直接放大理论价（均衡盘也封板）← 最隐蔽、最根本
├─ P2 金额比定价：单边即 Infinity/0 → 直接顶板
├─ P3 做市商深度固定 6000 股/轮，无法吸收单边压力
├─ P4 干预力度 3 倍于常规盘 + 干预价锚在涨停高价 + 干预后计数清零 → 锯齿振荡
├─ P5 tradePrice 不参与定价 → 收盘价不代表真实成交
└─ P6 零成交也动价 → 价格乱跳
```
