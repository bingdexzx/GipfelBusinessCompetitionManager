## 1. 系统概述

本系统是商业模拟竞赛（商赛）**办赛方**的桌面数据管理应用，采用 **C/S（Client/Server）** 架构：

- **办赛方**通过桌面客户端维护竞赛全量标准化数据（原料、零件、产品、地图、基建、科技树、燃料、载具、仓库、生产线、产业、公司、区域、合同、股票、消息等），配置比赛参数；
- **参赛选手**通过客户端获取竞赛数据、查看区域总览与股票行情、执行合同与交易。

### 1.1 核心设计目标

| 目标 | 实现方式 |
|------|----------|
| 标准化数据管理 | 25 个 Prisma 模型统一建模，全部业务数据按 `competitionId` 多租户隔离 |
| 配置驱动引擎 | 合同引擎（ContractEngine）、产业计算引擎（IndustryCalcEngine）、股票撮合引擎（engine.ts）均为配置/纯函数驱动 |
| 高效执行 | 数据懒加载、表格虚拟滚动、按需请求；IndexedDB 本地缓存（全量副本 + 增量基线）减少重复请求 |
| 实时同步 | Socket.IO 通用广播基建：Prisma 写操作后自动触发资源变更广播，客户端增量同步 |
| 权限分级 | RBAC 细粒度权限（31 个权限 key、18 个域）+ 5 个范围约束字段 + 三角色继承 |
| 安全可控 | JWT + 单设备互斥 + 强制改密 + 登录限流 + 审计日志 + 版本一致性硬封锁 |

### 1.2 关键设计决策（来自开发沉淀）

- **多租户约定**：`Competition` 是租户根；除 `User / Competition / FiscalYear / ContractType / IndustryType / IndustryField`（全局模板）外，其余业务实体均含可选 `competitionId`，读取/创建/删除全链路按比赛隔离，删除作用域由 `assertSameCompetition` 强制校验。
- **计算字段服务端权威**：产业计算图（calcGraph）由服务端在写入时级联重算，前端只展示服务端返回值，禁止本地重算（历史 `formula` 树为废弃路径）。
- **合同引擎可撤销**：合同执行产生的每次字段改写落为不可变 `ContractFieldEffect` 记录，删除合同时按 `executedAt` 顺序重放其余合同增量，精确撤销本合同影响而不污染后续合同。
- **股票引擎纯函数化**：撮合/定价/K 线生成全部收敛为可单测的纯函数（`engine.ts`），服务层只做状态落账与事务。
- **版本硬封锁**：客户端与服务端版本号不一致时锁定全部功能，每 5 分钟周期复核。

## 2. 总体架构

系统分三层：**客户端**（Electron + Vue 3）、**通信层**（HTTP REST + WebSocket 双通道）、**服务端**（NestJS + Prisma + SQLite）。

```
┌─────────────────────────────────────────────────────────────────┐
│                        客户端 (Electron + Vue 3)                  │
│  ┌───────────────────┐   ┌─────────────────────────────────────┐ │
│  │  Electron 主进程    │   │  Vue 3 SPA 应用层                    │ │
│  │  窗口管理 / IPC /   │   │  Router(23路由) · Pinia(6 Store)     │ │
│  │  本地存储 / 自动更新 │   │  API层(Axios+IndexedDB) · Realtime   │ │
│  └───────────────────┘   │  视图组件(ElementPlus/Konva/ECharts)  │ │
│                          └─────────────────────────────────────┘ │
└──────────────────────────────┬───────────────────────────────────┘
                               │
             ┌─────────────────┴─────────────────┐
             │ HTTP REST (JSON + JWT Bearer)      │ ← 主通道，基准 /api
             │ WebSocket (Socket.IO · 复用 3000)   │ ← 实时广播通道，JWT 握手
             └─────────────────┬─────────────────┘
┌──────────────────────────────▼───────────────────────────────────┐
│                        服务端 (NestJS 11)                         │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │  请求处理管线                                                  │ │
│  │  OperatorMiddleware → 安全头 → 登录限流 → CORS               │ │
│  │  → JwtAuthGuard → MustChangePassword → CompetitionScope     │ │
│  │  → OwnershipGuard → ValidationPipe → PermissionsGuard       │ │
│  │  → Controller → Service → PrismaService                     │ │
│  │  → ResponseInterceptor → LoggingInterceptor → ExceptionFilter│ │
│  └─────────────────────────────────────────────────────────────┘ │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │  业务模块层（modules/ 20 个业务模块 + auth/users/permissions │ │
│  │  + realtime，统一 Controller → Service → PrismaService 模式）│ │
│  └─────────────────────────────────────────────────────────────┘ │
│  ┌─────────────────────────────────────────────────────────────┐ │
│  │  数据访问层：Prisma ORM → SQLite (dev.db)                    │ │
│  │  $allOperations 审计中间件 · 写后自动广播 · Winston 日志       │ │
│  └─────────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

### 2.1 通信双通道

| 通道 | 用途 | 细节 |
|------|------|------|
| HTTP REST | 主数据通道 | 基准路径 `/api`；`Authorization: Bearer <JWT>`；统一响应体 `{ code, message, data }`；`GET ?updatedAfter=` 增量查询、`&requireExistingIds=` 对账 |
| WebSocket | 实时广播 | socket.io 复用 3000 端口；JWT 握手鉴权；`comp-{competitionId}` 房间 + `user-{userId}` 私有房间；强制改密用户禁止连接 |

## 4. 客户端架构

### 4.1 Electron 主进程

- **main.ts**：BrowserWindow 窗口管理、应用生命周期、菜单；
- **preload.ts**：`contextBridge` 安全暴露 IPC，隔离渲染进程权限；
- **utils/store.ts**：electron-store 持久化服务器地址、主题等本地配置。

### 4.2 Vue 3 SPA 应用层

| 子层 | 说明 |
|------|------|
| Router | Hash 模式 23 条路由；`beforeEach` 守卫依次做 JWT 有效性 → 强制改密 → 权限校验 → 重定向 |
| Pinia | 6 个 Store：`auth`（令牌/用户/登出）、`config`（服务器地址）、`competition`（当前比赛/财年/订阅）、`version`（版本封锁）、`announcement`（更新公告）、`message`（未读计数/收件箱） |
| API 层 | `request.ts`（Axios 实例：注入 JWT、解包响应、401 处理）；`cache.ts`（IndexedDB 全量副本 + 增量基线 + 对账）；`index.ts`（按资源封装的 API 集合） |
| Realtime | `socket.ts`（连接/重连）、`resource-changed.ts`（事件精确处理）、`useResourceChanged`（组件级订阅钩子） |
| 视图 | 登录、仪表盘（自定义控件）、数据管理（按 type 分发）、公司、比赛、区域总览、消息、股票行情/管理、账户、设置 |

### 4.3 本地缓存与增量同步（IndexedDB）

```
组件调用 API → _cachedGet(requestKey)
  ├─ 内存 memo 命中（15s 窗口内）→ 直接返回
  ├─ 本地有全量副本？
  │   ├─ 基线 <5min → GET ?updatedAfter=基线（增量）→ patchFullItems
  │   ├─ 基线 ≥5min → GET ?updatedAfter=基线&requireExistingIds=true → patch + diff 对账
  │   └─ 增量请求失败 → 返回本地副本（离线降级）
  └─ 本地无副本 → GET 全量 → 写本地副本 + 基线
写失效：POST/PUT/PATCH/DELETE 成功后按资源分组失效副本 + memo
实时事件：deleted → 精确移除本地项；created/updated → 失效 memo 触发增量重拉
```

## 5. 服务端架构

> 服务端当前设计问题（上帝模块 / 数据模型脆弱 / JSON 字符串泛滥 / 索引缺失 / 无测试 CI 等）与重构方案（服务拆分 / 数据加固 / 同步实时升级 / 安全可观测 / 测试 CI）详见 [`docs/后端重构设计.md`](后端重构设计.md)；本节为现状概述。

### 5.1 请求处理管线（13 步）

| # | 组件 | 职责 |
|---|------|------|
| ① | OperatorMiddleware | JWT 解析（不验签）→ AsyncLocalStorage 注入 `operator / requestId / ip`，供全链路日志溯源 |
| ② | securityHeaders | CSP（default-src 'none'）/ X-Frame-Options / CORP / Referrer-Policy |
| ③ | loginRateLimiter | 仅 POST /api/auth/login：IP+用户名 10 次/5 分钟 → 锁定 15 分钟（只计失败） |
| ④ | CORS | 白名单 / 本地网络反射（localhost、RFC1918、file://、app://） |
| ⑤ | JwtAuthGuard（全局） | Passport JWT 验证 + `tokenVersion` 单设备互斥；`@Public()` 可跳过 |
| ⑥ | MustChangePasswordGuard（全局） | `mustChangePassword=true` 拦截，仅放行改密/me |
| ⑦ | CompetitionScopeGuard（全局） | 多租户：自动注入/校验 `competitionId`；`@NoCompetitionScope()` 可跳过 |
| ⑧ | OwnershipGuard（全局） | 资源归属 BOLA 防御：实体与用户 `competitionId` 比对 |
| ⑨ | ValidationPipe（全局） | class-validator 白名单 + 类型转换 |
| ⑩ | PermissionsGuard（路由级） | `@RequirePermissions` RBAC 细粒度校验 |
| ⑪ | ResponseInterceptor | 统一 `{ code:0, message:"成功", data }` |
| ⑫ | LoggingInterceptor | 请求日志：方法/路径/状态/耗时/大小/operator |
| ⑬ | HttpExceptionFilter | 异常 → 中文错误信息 + Winston；5xx 不透出细节 |

### 5.2 PrismaService 扩展（横切能力）

- **审计中间件**：`$allOperations` 拦截写操作，记录 `before / after / changes`，密码/令牌/密钥键名脱敏；
- **自动广播**：写操作后经 `MODEL_TO_RESOURCE` 映射调用 `RealtimeService.emitResourceChanged`，业务代码零侵入。

## 6. 核心模块详解

> 服务端模块统一模式：`Controller（路由+权限装饰）→ Service（业务规则）→ PrismaService（数据访问）`。

### 6.1 认证与账户（auth / users / permissions）

- **Auth**：`POST /api/auth/login`（bcrypt 校验 + tokenVersion 自增 + 签发 JWT）、`GET /me`、`POST /change-password`。
- **Users**：账户 CRUD（需 `account:manage`），角色 `SUPER_ADMIN / COMPETITION_ADMIN / PLAYER`，含 5 个权限/范围 JSON 数组字段。
- **Permissions**：`PERMISSION_CATALOG` 权威定义 31 个权限 key、18 个域；`hasPermission()` 实现同域动作蕴含（`manage ⊇ edit ⊇ view`）；SUPER_ADMIN 隐式全放行。

### 6.2 比赛与财年（competitions）

- 比赛 = 租户根，删除级联清理其下全部业务数据（用户除外）；
- 财年：开/关状态切换驱动**财年定时器**（产业字段 `timerEnabled` 字段在 FY_START/FY_END 自动写入 `timerValue`，支持引用产业字段 `field:<fieldKey>`）。

### 6.3 生产链（materials / parts / products / tech-tree）

```
科技树(TechNode, DAG前置依赖)
   ├─ 需求 ──> 零件(Part) ──配比(PartMaterial)──> 原料(Material，按地图节点定价)
   └─ 需求 ──> 产品(Product) ──配比(ProductPart)──> 零件(Part)
                                        └─ 需求 ──> 消费者需求(ConsumerDemand)
```

- 原料 `nodePrices` 按地点（地图节点）定价，无基础价格字段；
- 科技树 `TechPrerequisite` 自引用实现 DAG 前置依赖；零件/产品经 `PartTechRequirement / ProductTechRequirement` 关联科技需求。

### 6.4 地图与物流（maps / infrastructures / fuels / vehicles / warehouses / production-lines）

```
MapNodeType ← MapNode ←1:N→ MapEdge → PathType
                              ↓
                        VehiclePathType ← Vehicle → Fuel
```

- 地图四类子资源（节点类型/路径类型/节点/边）按 `competitionId` 隔离；`getFullMap` 一次取全图；背景图 `Competition.mapBackground`（JSON）落盘 `server/uploads/map-backgrounds`；
- 基建 10 项属性；载具消耗燃料、可通过指定路径类型（`VehiclePathType` 连接表）。

### 6.5 产业系统（industry-types / companies / company-fields / regions / consumer-demands）

```
IndustryType(全局模板) → IndustryField(字段定义/计算图/财年定时器)
        ↓ 1:N
      Company(比赛实例, 归属 Region) → CompanyFieldValue(字段值)
```

- **产业字段**：STRING / NUMBER / BOOLEAN / DICTIONARY / LIST 五种类型；
- **计算字段**：`calcGraph`（GGraph JSON）由 `IndustryCalcEngine` 在写入时级联重算，服务端权威；
- **区域总览**：`Region.overviewCards`（JSON 卡片配置 `{id, displayName, companyId, industryFieldId}`）驱动前端数据框展示，卡片 id 为字符串（`c-${Date.now()}-${rand}`），前端禁止 Number() 转换；
- **消费者需求**：按区域记录产品需求，产品删除置空不级联（保留冗余 `productType` 名称）。

### 6.6 合同系统（contracts，配置驱动引擎）

```
ContractType(全局模板, key/partyRoles/inputSchema/effects/conditions/graph)
   → Contract(比赛实例, parties/inputs/status)
      → ContractFieldEffect(不可变字段改写记录: op ADD|SUB|SET, beforeRaw/afterRaw)
```

- **引擎流程**：前置检查（FIELD_COMPARE / VALUE_COMPARE / INDUSTRY_IS / DICT_COMPARE / LIST_COMPARE）→ 仅 FIELD 效果 → 改写 `CompanyFieldValue`；
- **可视化图编辑器**：`graph` JSON 存图结构，前端 `vue-flow` 风格编辑；
- **精确撤销**：删合同时按 `executedAt` 顺序重放其余已执行合同增量，不动后续合同已落账值。

> 合同类型配置与产业计算字段配置在「逻辑/公式复杂时界面混乱」的根因（value 万能节点、双图语义分裂、配置常量双份、JSON 无校验、画布缺工程化）与重设计方案（统一引擎 DSL、简单/专家双模式、图编辑器工程化、三层校验闭环、试算器）详见 [`docs/合同与字段表达式引擎重设计.md`](合同与字段表达式引擎重设计.md)。

### 6.7 股票系统（stock）

```
Stock(股票, 关联 Company) ──1:N──> StockOrder(委托)
StockFundsAccount(资金账户, COMPANY|USER) ──1:N──> StockOrder / StockHolding(持仓)
Stock ──1:N──> StockCandle(每轮一根K线)
```

- **轮次推进**（`POST /api/stocks/advance-round`，需 `stock:manage`）：
  1. `applyPbRound`：行业 PE 动态化（联动模式读 `pbCompanyId+pbFieldId` 实时字段 / 随机模式 `pbRandom` ±2 游走，钳制 [0,20]），`computeInitPrice` 重算初始价；
  2. `generateMarketMakerOrders`：AI 做市商（10 亿资金）当前价上下各挂 3 档（spread 2% 逐档加深），连续 2 轮涨/跌停大额反向干预；
  3. `advanceOneStock`：汇总 PENDING → `computeMatch`（最高买 ≥ 最低卖，成交价=(最高买+最低卖)/2）→ `computePrice`（上轮收盘 × 买卖盘比 × 幸福因子 × 碳因子，±10% 限幅）→ `buildCandle`；
  4. `$transaction` 落账：现金（绑定产业字段账户回写 `CompanyFieldValue`）、持仓、订单 FILLED/部分成交、K 线、currentPrice+round；
  5. 广播 `stock:round-advanced` + `resource:changed`。
- **字段绑定**：股票碳排/幸福度/行业均值可绑定区域总览卡片（实时值优先）；资金账户可绑定产业字段（现金与字段值双向同步）；
- **权限分级**：`stock:view`（行情/交易/自己账户）、`stock:edit`（低级管理，受 `stockCompanyScopes` 约束）、`stock:manage`（全量管理/推进轮次）。

> 股票「一字涨停/跌停」根因（幸福/碳因子放大、金额比定价、做市商深度、干预锯齿振荡）与优化方案（净买压力定价 / 因子解耦 / 流动性动态化 / 回归锚干预 / 参数配置化）详见 [`docs/股票系统优化设计.md`](股票系统优化设计.md)。

### 6.8 消息中心（messages）

```
Message(标题/内容/图片/ targetsAll / targetUserIds)
   → MessageRecipient(一次性结算收件人, read/readAt)
```

- 发布时按「本比赛全体」或显式选人批量结算收件人行，离线用户登录后仍可见；
- 在线用户收到 `message:new` 实时事件，屏幕右侧滑入弹窗；收件箱未读红点。

### 6.9 实时广播（realtime）

- `RealtimeGateway`：JWT 握手鉴权 → 自动加入 `user-{userId}` 房间 → `subscribe` 事件加入 `comp-{competitionId}` 房间（非超管仅能订阅自己的比赛）；
- `RealtimeService`：`emitResourceChanged(resource, id, action)` / `emitToUsers`；
- 事件类型：`resource:changed`、`fiscal-year:changed`、`competition:changed`、`company-field:changed`、`contract:changed`、`message:new`、`stock:round-advanced`。

### 6.10 文件服务（files）

- 地图背景图上传/删除/变换；消息图片上传（落盘 `uploads/message-images/`，删除消息时清理文件）。

## 7. 数据模型与关联

系统共 **25 个数据模型**（含连接表）。核心关联链：

```
Competition(租户根)
 ├─ FiscalYear         财年
 ├─ User               账户（permissions + 4 个范围字段）
 ├─ Company ─┬─> CompanyFieldValue ─> IndustryField ─> IndustryType(全局)
 │           └─> Region(overviewCards) ─> ConsumerDemand
 ├─ Material ──PartMaterial── Part ──ProductPart── Product
 ├─ TechNode ──TechPrerequisite(自引用) + Part/ProductTechRequirement
 ├─ MapNodeType ← MapNode ──MapEdge── PathType ← VehiclePathType ── Vehicle ── Fuel
 ├─ Infrastructure / Warehouse / ProductionLine
 ├─ ContractType ── Contract ── ContractFieldEffect
 ├─ Stock ── StockOrder / StockHolding / StockCandle；StockFundsAccount
 └─ Message ── MessageRecipient
```

设计要点：

- **多租户**：除全局模板（ContractType / IndustryType / IndustryField）与 User / Competition / FiscalYear 外，其余实体均带 `competitionId Int?`（null = 全局共享字典），名称唯一性为 `(competitionId, name)` 复合唯一；
- **删除策略**：业务从属数据级联删除（Cascade），产品被需求引用时 `SetNull` 保留记录，区域删除时公司 `regionId` 置空不删公司，股票删除时公司 `SetNull`；
- **JSON 字段**：范围/配置/图结构大量使用 JSON 字符串列（permissions、nodePrices、overviewCards、partyRoles、inputSchema、effects、conditions、graph、executionLog、images、targetUserIds、carbonFieldRef 等），SQLite 无原生 JSON 类型；
- **不可变审计**：`ContractFieldEffect` 是合同字段影响的唯一权威记录，支撑精确撤销。

> 完整字段定义以 `server/prisma/schema.prisma` 为准。

## 8. 核心数据流

### 8.1 业务请求数据流（读 / 写）

```
客户端组件 → API层(Axios: 注入JWT, 增量查询)
  → [HTTP + JWT Bearer]
  → 服务端守卫管线(中间件→全局守卫→权限守卫)
  → Controller → Service(业务规则/引擎)
  → PrismaService → SQLite
  → ResponseInterceptor {code,message,data}
  → 客户端：写成功后按资源失效缓存；读数据落 IndexedDB 副本 + 界面更新
```

### 8.2 实时广播数据流（写后同步）

```
任意 Service 写操作
  → PrismaService.$allOperations 审计钩子
  → RealtimeService.emitResourceChanged (MODEL→RESOURCE 映射)
  → Socket.IO → comp-{competitionId} / user-{userId} 房间
  → 客户端 socket.ts → resource-changed.ts
      ├─ deleted → 精确移除本地全量副本
      └─ created/updated → 失效 memo → 组件 useResourceChanged 增量重拉
  → 断线重连 → reconcileAllIncremental(requireExistingIds 对账)
```

### 8.3 合同执行数据流

```
① 管理员选择 ContractType + 填写 inputs + 选择参与方公司
   → POST /contracts（需 contract:manage；仅创建 DRAFT，不执行）
② 在草稿详情中为参与方填写合同编号（contract:manage / contract:execute 可改任意方；仅 audit 限所辖公司）
③ 列表/详情点击「执行」→ POST /contracts/:id/execute
   （ContractReviewGuard：contract:execute 或 contract:audit 任一；
    service.assertAuditScope：持 execute/manage 不受公司范围限制，仅 audit 按 companyScopes 过滤）
  → ContractEngine: 解析 effects → 逐条改写 CompanyFieldValue
  → 记录 ContractFieldEffect(beforeRaw/afterRaw) + executionLog
  → 状态置 EXECUTED + executedAt，广播 contract:changed + company-field:changed
  → 删除合同时：按 executedAt 重放其余合同增量，精确撤销
```

### 8.4 股票轮次推进数据流

见 [§6.7](#67-股票系统stock) 五步流程（下单 → 推进 → 做市商 → 撮合定价 → 事务落账 → 广播）。

### 8.5 本地缓存同步数据流

见 [§4.3](#43-本地缓存与增量同步indexeddb)（全量副本 → 增量基线 → 断线对账 → 写失效）。

> 本地存储隔离、增量同步防冲突、前端刷新与实时推送机制的重构方案详见 [`docs/数据同步与实时机制重构设计.md`](数据同步与实时机制重构设计.md)；前端界面刷新机制的专项重构方案（事件精确匹配 / memo 时序竞态 / 对账主动通知 / 账号级状态实时刷新）详见 [`docs/前端刷新机制重构设计.md`](前端刷新机制重构设计.md)；股票「一字涨停/跌停」问题的根因与优化方案详见 [`docs/股票系统优化设计.md`](股票系统优化设计.md)；本节为现状概述。

## 9. 权限与安全模型

> 权限分级模型（动作等级、角色模板、授予上限）与重构方案详见 [`docs/权限分级与重构设计.md`](权限分级与重构设计.md)；本节为现状概述。

### 9.1 权限模型（RBAC + 范围约束）

| 角色 | 权限语义 |
|------|----------|
| SUPER_ADMIN | 隐式拥有全部权限，始终放行 |
| COMPETITION_ADMIN | 数据查看 + 创建/执行/审核合同（contract:execute 比赛级执行，不受公司范围限制）+ 查看公司字段 + 股票低级管理/行情 + 区域总览 + 消息 |
| PLAYER | 数据查看 + 消息 + 区域总览 + 所选公司合同/字段查看 + 行情交易自己账户 |

- **权限 key 规范**：`<domain>:<action>`，如 `data:material:edit`、`contract:execute`；
- **动作蕴含**：同域内 `manage ⊇ edit ⊇ view`；`execute` / `audit` 需精确持有（不做向下蕴含）；空 `permissions` = 无数据访问；
- **合同执行权限语义**：`contract:execute` = 比赛级执行（不受公司范围限制，可执行本比赛内任意草稿合同）；`contract:audit` = 公司级执行（仅 `companyScopes` 范围内公司参与的合同）。前端执行按钮与后端 `assertAuditScope` 一致：持 execute/manage 全放行，仅 audit 时按行级参与公司预判。
- **5 个范围约束字段**（后端独立生效，前端简化界面由「身份+公司多选框」自动派生）：

| 字段 | 生效权限 | 语义 |
|------|----------|------|
| `permissions` | 全部 | 细粒度权限 key 列表 |
| `companyScopes` | contract:audit | 可审核合同的公司 id 范围 |
| `viewCompanyScopes` | company:view | 可读全量（含未发布）字段的公司范围 |
| `contractViewCompanyScopes` | contract:view | 可查看合同（按参与方公司匹配） |
| `stockCompanyScopes` | stock:edit | 可低级管理的公司资金账户范围 |

### 9.2 安全机制

- **认证**：JWT（24h，issuer/audience 绑定）+ 单设备互斥（tokenVersion 自增比对）+ 强制改密 + 登录限流（10 次/5 分钟锁 15 分钟）；
- **授权**：RBAC + 范围约束 + CompetitionScopeGuard（多租户）+ OwnershipGuard（BOLA 防御）；
- **传输**：CSP `default-src 'none'`、X-Frame-Options DENY、CORP、CORS 仅本地/内网反射；
- **输入**：ValidationPipe 白名单 + 类型转换；5xx 不透出细节；
- **审计**：Prisma 写操作全量审计（before/after/changes，密码脱敏），按 operator/requestId/ip 可回溯；
- **WebSocket**：JWT 握手鉴权、房间归属校验、强制改密用户禁止连接。

cd server && npm install && cp .env.example .env   # 配置 JWT_SECRET
npx prisma db push && npx prisma db seed           # 建表 + 默认超管 admin/admin123
