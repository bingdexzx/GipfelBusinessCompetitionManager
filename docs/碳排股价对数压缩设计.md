# 碳排对股价影响：对数压缩改造设计

> 状态：设计稿（待实现）｜2026-08-18
> 关联：`server/src/modules/stock/engine.ts` 的 `computeDrift` / `computePrice`；`StockConfig`（持久化于 `Competition.stockConfig` JSON）。
> 背景：见对话分析——当前线性归一在 `currentCarbon ≥ 2×industryAvgCarbon` 时 `c` 锁死在 `-1`，后期碳排指数级增长时股价完全不响应（"2× 封顶"）。

## 1. 现状与问题

碳排进入股价的唯一路径（`engine.ts` 的 `computeDrift`）：

```ts
const c =
  industryAvgCarbon !== 0
    ? clamp((industryAvgCarbon - currentCarbon) / industryAvgCarbon, -1, 1)
    : 0;
```

- `c` 为相对行业均值的线性偏离，被 `clamp(-1, 1)` 截断。
- 当 `currentCarbon ≥ 2×industryAvgCarbon` 时 `c` 恒为 `-1`（早饱和）。
- 后果：后期碳排指数级增长，但其对股价的压制力在 2× 处即封顶，曲线失真——指数增长在价格上不可见。
- 若 `industryAvgCarbon` 也绑定区域卡片同步增长，则比值恒定 `c≈0`，碳排对价格**完全无影响**。

## 2. 目标

用对数压缩替换线性归一，使 `c` 在碳排超过行业均值后仍随碳排增长而**持续（但递减）地更负**，消除早饱和。同时保留既有安全与不变量：

- `c(均值) = 0`、`c(R 倍均值) = -1` 的锚点（`R = carbonSaturateRatio` 可配，默认 `2`，与旧行为在 `≤2×` 段一致）；
- 碳排 `= 0` 时 `c = +1`（最优）；
- 数值恒有限，不溢出、不产生 `NaN`/`Infinity`；
- 单轮价格仍受 `limitPct` 硬限幅（`±10%`）兜底，不会因 `c` 变负而失控。

## 3. 公式

```
c = min(1, -ln(currentCarbon / industryAvgCarbon) / ln(R))
```

- `R = carbonSaturateRatio`（默认 `2`）。
- **不钳制下界**：`c` 可随碳排无限变负，但被 `computePrice` 的 `±limitPct` 硬限幅兜底；对数本身已把"指数增长"压缩为"线性变负"，逐轮跌幅递减、不会爆。
- `industryAvgCarbon ≤ 0` → 返回 `0`（无法归一，原样保留旧行为）。
- `currentCarbon ≤ 0` → 返回 `+1`（零碳排视为最优）。

性质（单调、连续、无早饱和）：

| 碳排 / 均值 (r) | 0⁺ | 0.5 | 1 | R(=2) | R²(=4) | R³(=8) |
|---|---|---|---|---|---|---|
| c | +1 | +1 | 0 | -1 | -2 | -3 |

对比旧线性式：`r≥2` 一律 `-1`（封顶），新式为对数持续下探。

## 4. 实现改动

### 后端 `engine.ts`
1. `StockConfig` 接口增加 `carbonSaturateRatio: number`；`DEFAULT_STOCK_CONFIG` 同步 `carbonSaturateRatio: 2`。
2. 新增纯函数 `computeCarbonDrift(currentCarbon, industryAvgCarbon, carbonSaturateRatio = 2): number`，实现 §3 公式；`ln(R)` 取 `R > 1 ? R : 2` 防除零。
3. `computeDrift` 末位新增形参 `carbonSaturateRatio: number = 2`（默认 2，**向后兼容**既有 5 参调用），内部改调 `computeCarbonDrift`。
4. `computePrice` 透传 `f.config.carbonSaturateRatio` 给 `computeDrift`。

### 持久化
- `Competition.stockConfig` 为 `Json?`，新增字段无需 Prisma 迁移；`resolveStockConfig` 合并默认值即可生效。

### 前端（镜像，保持一致）
- `client/src/api/index.ts`：`stockConfig` 类型增加 `carbonSaturateRatio?: number`。
- `client/src/views/stocks/StockManageView.vue`：`stockConfigForm` 默认值增 `carbonSaturateRatio: 2`，并在碳排相关输入区增一个数值输入项（与 `carbonImpact` 并列）。

## 5. 测试 `engine.spec.ts`
- 更新「碳排低于均值」用例：`currentCarbon=50`（均值 100）→ `c=+1` → `drift≈0.2`（原期望 `0.1`，因旧线性式给 `0.5`）。
- 新增「碳排远超均值仍持续响应」用例：
  - `currentCarbon=400`（4×）→ `c=-ln(4)/ln(2)=-2` → `drift≈-0.4`；
  - `currentCarbon=800`（8×）→ `c=-3` → `drift≈-0.6`。
  证明碳排继续翻倍、股价压制力持续增强（不再 2× 封顶）。

## 7. 开放点（实现后视情况再议，本次不做）
- 是否需要把 `c` 的下界也钳到一个较小负值（如 `-6`）以彻底限定逐轮碳排拖拽上限？当前依赖 `limitPct` 兜底，已足够安全；若实操发现单股碳排拖拽过猛再议。
- `industryAvgCarbon` 同步指数增长导致碳排失效的问题，属"动态基线"议题，不在本次对数压缩范围内。
