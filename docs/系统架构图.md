## 3. 服务端架构详解

### 3.1 请求处理管线（中间件/守卫/拦截器/过滤器顺序）

| 顺序 | 组件 | 文件位置 | 职责 |
|------|------|---------|------|
| 1 | OperatorMiddleware | `common/logging/operator.middleware.ts` | 解析JWT→写入AsyncLocalStorage（operatorId/role/competitionId/requestId） |
| 2 | securityHeaders | `main.ts`内联 | CSP / X-Frame-Options / CORP 安全响应头 |
| 3 | loginRateLimiter | `common/security/login-throttle.ts` | IP+用户名 10次/5分钟 → 锁定15分钟（登录端点） |
| 4 | CORS | `main.ts`内联 | 白名单来源校验，支持本地网络反射/Electron |
| 5 | JwtAuthGuard | `common/guards/jwt-auth.guard.ts` | JWT签名校验 + tokenVersion单设备互斥 |
| 6 | MustChangePasswordGuard | `common/guards/must-change-password.guard.ts` | mustChangePassword=true时除改密接口外全部拦截 |
| 7 | CompetitionScopeGuard | `common/guards/competition-scope.guard.ts` | 多租户：非超管强制收敛competitionId到本人所属比赛 |
| 8 | OwnershipGuard | `common/guards/ownership.guard.ts` | BOLA防御：校验资源归属（基于路径参数id查表） |
| 9 | ValidationPipe | NestJS内置 + DTO装饰器 | class-validator白名单校验 + 类型转换 |
| 10 | PermissionsGuard | `permissions/permissions.guard.ts` | RBAC：读取@RequirePermissions，AND语义 + 动作等级蕴含 |
| - | Controller/Service | `modules/*/` | 业务逻辑处理 → PrismaService |
| 11 | ResponseInterceptor | `common/interceptors/response.interceptor.ts` | 统一包装 { code:0, message:"成功", data } |
| 12 | LoggingInterceptor | `common/interceptors/logging.interceptor.ts` | 请求日志：方法/路径/状态/耗时/响应大小/operator |
| 13 | HttpExceptionFilter | `common/filters/http-exception.filter.ts` | 异常捕获→中文错误信息+Winston上下文日志 |

## 4. 数据模型关系（核心实体）

```
User ── competitionId ──→ Competition ──┬──→ FiscalYear
  │                                     ├──→ Material / Part / Product
  │  role: SUPER_ADMIN /                ├──→ MapNode / MapEdge / PathType
  │        COMPETITION_ADMIN / PLAYER   ├──→ Infrastructure / Warehouse
  │  permissions[] (JSON)               ├──→ Fuel / Vehicle
  │  4× companyScopes (JSON)            ├──→ Region → ConsumerDemand
  │                                     ├──→ IndustryType → IndustryField
  │                                     └──→ Company → CompanyFieldValue
  │
  ├──→ Message (senderId) → MessageRecipient (userId)
  └──→ StockFundsAccount (userId) → StockOrder → StockHolding

ContractType (全局模板)
  ├── partyRoles[] (参与方定义)
  ├── inputSchema (输入表单定义)
  ├── conditions[] (签约前置条件)
  ├── effects[] (执行效果列表)
  └── graph (可视化流程图 GGraph)

Contract (比赛实例) ← competitionId
  ├── contractTypeId
  ├── partyAssignments (参与方→公司/用户映射)
  ├── inputValues (输入表单值)
  ├── status: DRAFT / EXECUTED / CANCELLED
  └── ContractFieldEffect (执行后字段改写记录)

Stock ← competitionId
  ├── StockOrder (BUY/SELL, price, quantity, status)
  ├── StockHolding (companyId ↔ stockId, shares)
  └── StockCandle (轮次K线: open/close/high/low/volume)
```

### 5.1 动作等级蕴含规则（代码权威）

**全局默认等级**（`DEFAULT_ACTION_RANKS`）：

| 动作 | rank | 说明 |
|------|------|------|
| view | 10 | 只读 |
| edit | 20 | 数据写（增删改） |
| manage | 30 | 管理操作 |
| execute | 40 | 执行类操作 |
| audit | 50 | 审核类操作 |

**合同域自定义等级**（`contract.actionRank`）：

| 动作 | rank | 蕴含关系 |
|------|------|---------|
| view | 10 | 最低 |
| audit | 20 | ⊇ view |
| execute | 30 | ⊇ audit ⊇ view |
| manage | 40 | ⊇ execute ⊇ audit ⊇ view（最高） |

**判定算法**（`hasPermission`）：
1. SUPER_ADMIN → 直接 true
2. 用户权限集精确匹配 required → true
3. 否则解析 `domain:action`，取该域等级表
4. 遍历用户同域所有动作，若存在 rank ≥ requiredRank → true
5. 全部不满足 → false
