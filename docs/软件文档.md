## 1. 系统概述

### 1.1 定位与目标用户

Gipfel 商赛办赛辅助系统是面向**商业模拟竞赛办赛方**的桌面数据管理与赛事运营工具。典型场景：
- 高校/中学商赛社团举办校内/地区级比赛；
- 教育机构组织产业模拟教学活动；
- 企业内部商业沙盘培训。

目标用户角色：
| 角色 | 对应系统角色 | 主要职责 |
|------|-------------|----------|
| 系统运维 | `SUPER_ADMIN` | 创建比赛、管理全部账号、分配比赛管理员 |
| 赛事主办 / 裁判 | `COMPETITION_ADMIN` | 在指定比赛中维护基础数据、配置产业/合同/股票、审核合同、发布公告 |
| 参赛选手 / 公司代表 | `PLAYER` | 查看数据、签合同、操作股票（权限依授予范围） |

### 1.2 系统边界

本系统是**办赛方管理后台**，**不是**面向选手的比赛参与端（选手端通常由办赛方另行开发或直接通过 Excel / 本系统只读账号使用）。系统内所有"选手账号"通常由办赛方人员代操作，或授予只读 + 股票/合同的操作权限。

## 3. 环境配置与启动

### 3.1 依赖安装（三处 workspace）

```
shared/engine-dsl  →  npm install   (engine-dsl 本身零依赖，tsconfig 仅有 TS@5)
server/            →  npm install   (约 140MB node_modules)
client/            →  npm install   (约 480MB node_modules，含 Electron)
```

Windows 下直接双击 `tools\install_deps.bat`，内部顺序执行三处 `npm install`（遇镜像问题脚本默认会尝试切换 npmmirror）。

### 3.2 服务端环境变量 `server/.env`

模板 `server/.env.example` 字段全量说明：

| 变量 | 默认值 | 必填 | 说明 |
|------|--------|------|------|
| `PORT` | `3000` | 否 | 服务端监听端口；REST + Socket.IO 复用；Electron 客户端默认连接此端口 |
| `DATABASE_URL` | `file:./dev.db` | 否 | SQLite 文件路径（相对 server/prisma/）；绝对路径需写 `file:/absolute/path` |
| `JWT_SECRET` | 模板值 `your-dev-secret...` | **是** | JWT HS256 签名密钥；未配置时 JwtStrategy/JwtService 会抛错导致服务无法启动。生产务必：`openssl rand -hex 32` |
| `JWT_EXPIRES_IN` | `24h` | 否 | 令牌有效期；格式见 [ms 库](https://github.com/vercel/ms)：`1h` / `30m` / `7d` |
| `JWT_ISSUER` | `gipfel-competition` | 否 | 签发者声明 `iss`；JwtStrategy 校验、WebSocket 握手校验均绑定，防止其它系统令牌误用 |
| `JWT_AUDIENCE` | `gipfel-competition-client` | 否 | 受众声明 `aud`；同上双重绑定 |
| `LOG_LEVEL` | `info` | 否 | Winston 级别：error < warn < info < debug；生产建议 info，调试用 debug |
| `LOG_DIR` | `./logs` | 否 | 日志文件目录（相对 server/）；DailyRotateFile 按天切割：`application-YYYY-MM-DD.log` + `error-YYYY-MM-DD.log` |
| `UPLOAD_DIR` | `process.cwd()/uploads` | 否 | 用户上传落盘目录（地图背景图 / 消息图片）；`main.ts` 中挂在 `/uploads` 路由 |
| `CORS_ORIGIN` | 未设置 | 否 | 逗号分隔可信来源白名单。**未设置**：仅 localhost / 回环 / RFC1918 私网 / `file:` / `app:` 协议反射放行（带 credentials），公网来源一律拒绝；**设置具体域名**：严格白名单命中；**设置 `*`**：同未设置行为（`*` 不作为公网通配，避免误开）。桌面部署无需配置；若同时有 Web 前端访问公网域名必须显式加入。 |

`.env` 的读取链：`main.ts` 首行 `import 'dotenv/config'` → `process.env` → `ConfigModule.forRoot()` 封装 → `ConfigService`。

### 3.3 数据库初始化

```bash
cd server
# 方式 1：db push（推荐开发 / 快速迭代 —— 不生成 migration 历史，同步 schema 到库）
npx prisma db push

# 方式 2：生成正式 migration（生产推荐，可回滚）
npx prisma migrate dev --name init

# 可选：用 seed.ts 写入默认超管（效果等同 main.ts bootstrap 自动创建）
npx prisma db seed
```

若 `server/prisma/dev.db` 文件不存在，`db push` 会自动创建它及全部 34 张表 + 索引 + 外键。

> ⚠️ **注意**：删除 DB 后首次启动服务端时，`main.ts bootstrap()` 会自动查询 `admin` 用户，不存在则创建（`username=admin`，`passwordHash=bcrypt('admin123', cost=12)`，`role=SUPER_ADMIN`，`mustChangePassword=true`）。这与 `prisma/seed.ts` 完全等价。两种方式任选其一即可，不会重复创建（username 唯一）。

### 4.3 server/src/auth/ 认证模块

- `auth.controller.ts` 路由：
  - `POST /api/auth/login`（`@Public()`，无鉴权）：body `{username, password}` → 校验限流 → bcrypt 比对 → 签发 JWT（含 sub=userId, role, competitionId, tokenVersion, displayName, expiresAt）→ 返回 `{accessToken, user:{...}, permissions:[...], version:"1.3.16"}`。
  - `POST /api/auth/change-password`：body `{oldPassword, newPassword}` → 校验旧密码 → 写入新密码哈希 → 清除 mustChangePassword 标志 → **自增 tokenVersion（顶掉其它所有已登录设备，避免改密后旧令牌仍有效）**。
  - `GET /api/auth/me`：返回当前完整 user 实体（含反序列化后的 permissions/scopes 数组）。
- `auth.service.ts`：
  - `validateUser(username, password)`：bcrypt.compare → 成功 `clearLoginFail`，失败 `recordLoginFail` 并抛 401。
  - `login(user)`：构造 payload 调 `jwtService.sign(payload,{expiresIn,issuer,audience})`。
  - `changePassword(userId, old, new)`：调用 usersService 更新 + `clearLoginFail(userId)` + **tokenVersion++**。
- `strategies/jwt.strategy.ts`：`PassportStrategy(Strategy)` 从 `Authorization: Bearer <token>` 取 token，verify 时强制 issuer/audience；decode payload.sub → 查 DB User 实体 → 比对 tokenVersion（不一致 = 已被顶号，抛 401 "登录已失效，账号在其他设备登录"）→ 写 `req.user = userEntity`。

### 4.4 server/src/users/ 账户模块

- `users.controller.ts` REST：
  - `GET /api/users`（account:manage）：分页 + 按 competitionId 过滤；SUPER_ADMIN 可跨比赛查看。
  - `POST /api/users`（account:manage）：创建用户；body 含 role / permissions 数组 / scopes。内部：`assertGrantAllowed(SUPER_ADMIN, target.role, permissions)` 校验授予上限；password 走 IsStrongPassword 校验 → bcrypt → 哈希；permissions 走 `serializePermissions()` 存 JSON 字符串；scopes 4 个字段分别 `serializeCompanyScopes()`。
  - `PATCH /api/users/:id`（account:manage）：更新用户，权限写入同上 assertGrantAllowed 校验；改 role 时自动用 `getDefaultPermissions(role)` + `getDefaultScopes(role)` 回填（若 body 未显式传）。
  - `DELETE /api/users/:id`（account:manage）：删除用户；仅非自身；**同时 user.id 作为 Message.senderId 的消息不删（历史留存），但 MessageRecipient 级联**。
  - `GET /api/roles/templates`：返回 `ROLE_TEMPLATES`（前端新建账号时默认填充用）。
  - `POST /api/users/:id/reset-password`：重置密码为随机字符串，返回明文；mustChangePassword=true。

### 4.5 实时通信 server/src/realtime/

- `realtime.gateway.ts`：`@WebSocketGateway()`（与 HTTP 同端口，无额外端口）。
  - CORS：`WS_ALLOWED_ORIGINS` 从 `process.env.CORS_ORIGIN || "http://localhost:5173,http://localhost:3000,app://localhost"`；规则与 HTTP 侧一致（白名单命中 + 无 Origin 放行）。
  - `handleConnection(client)`：从 handshake `auth.token` 或 `query.token` 取 JWT；`jwtService.verify(raw, {issuer, audience})`；查 user；**mustChangePassword=true → `emit('auth:required')` 后立即断开**（与 HTTP 侧 MustChangePasswordGuard 策略一致）；写入 `client.data`（userId/role/competitionId）→ `join('user-${userId}')` 私有房间。
  - `handleDisconnect(client)`：socket.io 自动清理所有房间。
  - `@SubscribeMessage('subscribe')`：body `{competitionId}`；**房间归属校验**：role≠SUPER_ADMIN 且 cid≠ownCid → 发 `subscribe:denied`；否则 `join('comp-${cid}')`。
  - `@SubscribeMessage('unsubscribe')`：离开比赛房间。
  - `@SubscribeMessage('sync:replay')`：body `{afterSeq}` → 调 `realtime.getEventsAfter(seq)` → 发 `sync:replay:result {events, serverSeq}`（`serverSeq` 为服务端当前序号基线，供前端判断服务端是否重启过：若 `serverSeq < afterSeq` 说明序号已回退，前端应重置基线并依赖全量对账，而非信任增量 replay）。
- `realtime.service.ts`：
  - `setServer(server)` 保存 Socket.IO Server 引用。
  - `_eventSeq` 自增序列号、`_eventBuffer`（环形数组，默认保留最近 1000 条全局广播事件，按 seq 索引）。
  - `broadcastResourceChange({competitionId, model, action, id, data})`：写入 `_eventBuffer` 加 seq；向 `comp-${competitionId}` 房间发 `resource:changed {seq, ts, payload}`；同时若涉及用户私有资源（Message 收件箱等）额外 emit `user-${userId}`。
  - `getEventsAfter(afterSeq)`：返回 buffer 内 seq > afterSeq 的事件数组（用于重连补发）。

### 4.6 PrismaService server/src/prisma/prisma.service.ts

```ts
@Injectable()
export class PrismaService extends PrismaClient implements OnModuleInit, OnModuleDestroy {
  constructor(private readonly realtime: RealtimeService) { super({ log:['warn','error'] }); }
  async onModuleInit() { await this.$connect(); this.installMiddleware(); }
  async onModuleDestroy() { await this.$disconnect(); }

  private installMiddleware() {
    this.$use(async (params, next) => {
      const action = `${params.model}:${params.action}`; // e.g. "User:update"
      const before = (params.action in ['update','upsert','delete','deleteMany'])
        ? await this.queryBefore(params) : null;   // 快照原值（before 用于 AuditLog + 删除影响）
      const result = await next(params);             // 执行实际 DB 写
      // —— 写操作后三件套：——
      // 1) 审计日志
      if (params.action in ['create','update','upsert','delete','deleteMany','createMany','updateMany'])
        writeAudit(params.model, params.action, idOf(result), before, result);
      // 2) 实时广播（资源变更）
      if (isWriteOp(params.action) && params.model !== 'AuditLog') {
        const competitionId = extractCompetitionId(params, result); // 从 data 或 where 路径推断
        if (competitionId != null)
          this.realtime.broadcastResourceChange({competitionId, model:params.model, action:params.action, id:idOf(result), data:result});
      }
      // 3) （可选）乐观锁自增由具体 Service 的 update 中手写，middleware 不自动做（避免误改 version）
      return result;
    });
  }
}
```

> 关键点：AuditLog + Realtime 两条横切逻辑**完全靠 Prisma Middleware 保证落库与广播**，业务 Service 无需手动写。读操作不走 middleware（无副作用）。

#### 4.7.6 industry-types（产业类型 + 产业字段 + 计算引擎）

核心模块之一，是"公司字段 → 合同执行 → 区域总览 → 股票联动"整条链路的数据定义真源。

**IndustryType**：
- `code Int @unique`（产业类型编码，如 1=制造业、2=金融业，办赛方自定）、`name`、`description?`、`icon?`。

**IndustryField**（产业字段）：
- 5 种 `fieldType`（String，非枚举因为 SQLite）：
  1. `STRING` —— 文本字符串（CompanyFieldValue.value 直接存）。
  2. `NUMBER` —— 数值（value 存 JSON-number 字符串，合同 ADD/SUB 时 parseFloat）。
  3. `BOOLEAN` —— 真假（存 "true"/"false"）。
  4. `DICTIONARY` —— 字典（`config JSON: { entries:[{key,label,defaultValue}], valueType:"STRING|NUMBER|BOOLEAN" }`，value 存 JSON `{key1:val1,key2:val2}` 字符串）。
  5. `LIST` —— 列表（`config JSON: {itemType:"STRING|NUMBER|BOOLEAN"}`，value 存 JSON 数组字符串）。
- `isCalculated Boolean`（默认 false）+ `calcGraph String?`：**计算字段**。`calcGraph` 是产业计算图（GGraph JSON，见 contracts/graph-model.ts + IndustryFieldGraphEditor.vue）。写其它 IndustryField → 触发 IndustryCalcEngine 级联：拓扑排序 → 重新计算所有受影响的 calc 字段值。
- `formula String?`：**旧公式引擎遗留列**，仅为兼容历史数据保留，实际计算走 calcGraph；前端编辑不再暴露此列。
- `visible Boolean`（默认 true）：展示层开关。false 时字段不出现在公司管理 / 区域总览字段选择 / 合同编辑器字段目标等任何 UI 中；合同引擎仍按 fieldKey 正常读写其 CompanyFieldValue（不影响后台执行）。
- `timerEnabled + timerTrigger + timerValue`：**财年定时器字段**。FY_START（财年激活）或 FY_END（财年关闭）时自动给该产业类型下全部公司字段写 timerValue（按 fieldType 序列化）；与 isCalculated **互斥**（计算字段写入即被级联重算覆盖，定时器无意义），DTO create/update 时校验二选一开。
- `sortOrder Int`：前端字段编辑 / 公司详情表单排序。
- 唯一约束 `@@unique([industryTypeId, fieldKey])`。

**IndustryCalcEngineService**（单元测试 `industry-calc-engine.service.spec.ts`）：
- `recalculateForField(changedFieldId)`：某字段写 → BFS 图遍历找出依赖它的全部计算字段 → 拓扑排序（DAG，含循环检测）→ 依次重算 CompanyFieldValue。
- `evalNode(node, companyId)`：执行 GGraph 节点（INPUT 节点取 CompanyFieldValue，OP 节点走 safe-expression 的 mathjs 沙箱）→ 回写结果 → 记录乐观锁 version。
- `recalculateAllForIndustry(industryTypeId)`：产业类型新建/字段变更时，一次性重算所有公司所有计算字段到基线。

#### 4.7.7 companies + company-fields

- **Company**：name（比赛内建议唯一，非 DB 级约束）、industryTypeId、regionId（删除 Region 时 SetNull）、status（ACTIVE 默认 / ARCHIVED）。
- **CompanyFieldValue**：`@@unique([companyId, industryFieldId])`、`value String`（按 fieldType 序列化后的字符串）、`version Int @default(0)`（**乐观锁**）。

CompanyFieldsService 写路径（核心并发控制）：
```
upsertFieldValue(companyId, industryFieldId, newValue)
  1. 查当前行（含 version）→ 不存在则 create({version:1}); 存在则进入第 2 步。
  2. updateMany({ where:{companyId, industryFieldId, version}, data:{value, version:{increment:1}} })
     → 受影响行数 = 0 表示并发冲突，抛 FieldWriteConflictException（HTTP 409）。
     → 前端捕获 409 后弹出"该字段已被他人修改，已刷新最新值，请重新操作"并重读。
  3. 写入成功后 → 若该 industryField.isCalculated=false → 触发 IndustryCalcEngine.recalculateForField(fieldId)
     （级联重算依赖它的所有计算字段，级联内乐观锁相同，若级联失败整事务回滚）。
```
> 注意：calcGraph 字段本身**不接受直接 upsert**（Service 内判断 isCalculated=true 抛 400 "计算字段不可直接写入"），始终由引擎写入。

CompanyService.delete(companyId)：
- 级联删 CompanyFieldValue（Prisma onDelete Cascade）。
- 调用 `field-ref-cleanup.ts` 清理：Region.overviewCards 中该公司的卡片 / Stock.companyId 置 SetNull / Contract parties 中引用的 companyId 保留（合同历史不可变）但 contract:view 权限基于 scopes 时自动失效。

#### 4.7.9 contracts（合同系统：配置 + 引擎）

最大业务模块，文件数最多，分模块拆分：
```
contracts/
```

**ContractType**（配置模板）：
- `key @unique`：英文编码，如 `LOAN` / `FUEL_PURCHASE` / `RND`。
- `partyCount 2|3`；`partyRoles JSON`：
  ```json
  [
    {"role":"A","label":"放款方","selectable":true,"isHost":false},
    {"role":"B","label":"借款方","selectable":true,"isHost":true},
    {"role":"C","label":"担保方","selectable":true,"isHost":false}
  ]
  ```
- `inputSchema JSON`：表单参数定义数组，每个元素 `{key,label,type:"NUMBER|STRING|BOOLEAN|DICT", required:bool, default?, options?}`。Contract 实例的 inputs JSON 必须匹配此 schema（Zod 校验，见 contract-type.dto.ts）。
- `effects JSON`：效果数组，核心执行单元（引擎只支持 FIELD 效果，不再有跨表/转账等复杂效果——全收敛到产业字段）：
  ```json
  [
    {"id":"e1","type":"FIELD","targetRole":"B","fieldKey":"cash_account","op":"ADD","valueExpr":"inputs.amount"},
    {"id":"e2","type":"FIELD","targetRole":"A","fieldKey":"loan_receivable","op":"ADD","valueExpr":"inputs.amount"}
  ]
  ```
  `op ∈ {ADD, SUB, SET}`；`valueExpr` 走 safe-expression mathjs 沙箱，可用变量：`inputs.*`（输入参数）、`fields.<role>.<fieldKey>`（各方当前字段现值，见 engine/values.ts resolve）。
- `conditions JSON`：前置检查数组（不通过时不能签合同 → 抛 422）：
  ```json
  [
    {"type":"FIELD_COMPARE","targetRole":"B","fieldKey":"cash_account","op":"GTE","valueExpr":"inputs.amount"},
    {"type":"INDUSTRY_IS","targetRole":"B","industryCode":7}  # B 方必须是产业 code=7 的公司
  ]
  ```
- `graph JSON`：可视化编辑器图结构（ContractTypeGraphEditor.vue 产成），与 effects/conditions 双向同步。
- `schemaVersion Int`、`enabled Boolean`（enabled=false 的合同类型前端不展示在新建合同的可选列表，但历史合同仍可读）。

**ContractEngineService**（核心执行路径）：
```
executeContract(contractId) 事务：
  1) 取 contract + contractType + 所有 parties 对应公司 + 所有 target fieldKey 的 CompanyFieldValue（加悲观？不，用乐观锁 version）。
  2) EngineConditions.checkAll(conditions, parties, fields, inputs) → 任一失败抛 422，含具体失败项 message。
  3) EngineEffects.plan(effects, parties, fields, inputs) → 产出 effectPlans[]：
     {companyId, industryFieldId, fieldKey, fieldName, op, value, beforeValue}
  4) 逐个 effectPlan 执行 CompanyFieldsService.upsertFieldValue(companyId, fieldId, newValue, {...})
     → 级联 IndustryCalcEngine 计算字段重算（内部同事务）；若任一字段 version 冲突抛 FieldWriteConflict → 全事务回滚。
  5) 写入 ContractFieldEffect 行（对每个 effectPlan：beforeRaw/afterRaw/valueRaw/op/fieldKey/...），按 executedAt 排序（用于后续撤销）。
  6) 更新 Contract.status=EXECUTED + executedAt=now + executionLog(JSON 执行审计) + executionResult(JSON 关键摘要)。
  7) Prisma middleware 自动写 AuditLog + 实时广播。
```

**Contract 删除（撤销）**：
```
remove(contractId) 事务：
  前提：该 contract.status=EXECUTED（草稿直接删，无撤销步骤）。
  1) 取本合同的所有 ContractFieldEffect（按 id ASC）。
  2) 取该比赛中**其它**所有 EXECUTED 合同，按 executedAt ASC 排序（含它们的 effects）。
  3) 对本合同影响到的每一个 (companyId, industryFieldId) 字段：
     a. 找删除"本合同前"的基线值（合同创建时的快照 beforeRaw）。
     b. 按时间顺序**重放其它所有已执行合同中**针对该字段的 effect（ADD/SUB/SET 逐一 apply）。
     c. 计算出最终 newValue → 用乐观锁 upsert 写回 CompanyFieldValue。
  4) 删除 Contract 行 → ContractFieldEffect 通过 onDelete Cascade 自动清理。
  5) IndustryCalcEngine.recalculateForField(受影响的所有字段) → 计算字段级联。
```
> 这种"删除合同时精确撤销 + 后续合同结果保持不变"的机制依赖 ContractFieldEffect 的不可变性，不再需要 full event sourcing。

**合同审核流**（status = PENDING_EXEC → EXECUTED）：
- ContractService.submitForReview(contractId)：DRAFT → PENDING_EXEC。
- ContractService.auditApprove(contractId, auditorId, opinion?) / auditReject(...): PENDING_EXEC → 审核通过（可被 contract:execute 执行或退回 DRAFT）；ContractReviewGuard 校验 auditor 持 `contract:audit` 且 parties 中所有公司在其 `companyScopes`（JSON 公司 id 数组）范围内。
- ContractService.execute(contractId)：PENDING_EXEC → EXECUTED；`contract:execute` 权限即可，不受 companyScopes 限制（execute 是比赛级权限，通常由主裁判操作）。
- 合同编辑/删除：ContractEditGuard；EXECUTED 后删除走撤销路径，DRAFT/PENDING_EXEC 普通删除。

#### 4.7.11 stock（股票系统：撮合 + 定价 + K 线）

独立引擎 `modules/stock/engine.ts`（纯函数，有 `engine.spec.ts` 单测覆盖）；StockService 封装 DB 读写。

**数据结构复习**（schema.prisma）：
- Stock：基础字段（totalShares/initNetProfit/industryPE/currentCarbon/industryAvgCarbon/happiness），**绑定引用**（carbonFieldRef / happinessFieldRef / industryAvgCarbonRefs JSON → Region.overviewCards），**PE 模式**（pbCompanyId+pbFieldId 联动模式 / pbCompanyId 空 → pbRandom 0~20 ±2 游走模式），运行时（initPrice/currentPrice/round）。
- StockFundsAccount：ownerType `COMPANY | USER` + companyId / userId；cashBalance Float；bindFieldId（可选，产业字段 id）→ 每次 cashBalance 变更时同步把值写入 CompanyFieldValue（让产业字段中看到现金实时值，合同引擎也能操作）。
- StockHolding：`@@unique([fundsAccountId, stockId])`，shares + costPrice。
- StockOrder：side BUY/SELL，price，quantity，amount，round，status；index `[competitionId, stockId, round, status]` 加速撮合查询。
- StockCandle：`@@unique([stockId, round])`，open/high/low/close/changePct。

**轮次推进核心流程** `StockService.advanceRound(competitionId, stockId? | 'ALL')`：

```
1) 快照：对该比赛/该股票所有 Stock，计算本轮到当前 PE 值
   a. 联动模式：pbCompanyId + pbFieldId 非空 → 取 CompanyFieldValue 数值 → 写回 Stock.industryPE 缓存
   b. 随机模式：pbRandom = clamp(pbRandom + random(-2,+2), 0, 20) → industryPE = pbRandom
   c. 同理解析 carbonFieldRef、happinessFieldRef、industryAvgCarbonRefs → 覆盖 Stock.currentCarbon / happiness / industryAvgCarbon 实时值（绑定了区域总览的就按字段实时值，否则保留手动值）

2) 撮合（每只股票）：
   a. 取所有 StockOrder 其中 competitionId=比赛, stockId=stock, round=currentRound, status=PENDING
      分为 buyList(price DESC) / sellList(price ASC)。
   b. 双指针撮合：当 buyList[0].price >= sellList[0].price 时成交；成交价 = (buy+sell)/2（或简化：买单价）。成交量 = min(buy.quantity, sell.quantity)。
      - 买方：持仓 StockHolding shares += 成交；costPrice = 加权 = (原 cost*原 shares + 成交*成交价)/(原 shares+成交)；资金账户 cashBalance -= 成交*成交价；bindFieldId 同步。
      - 卖方：shares -= 成交；cashBalance += 成交*成交价；bindFieldId 同步。
      - StockOrder：PENDING → FILLED；quantity=剩余（部分成交保留 PENDING）。
   c. 未成交订单（PENDING 本轮）→ 本轮结束后 CANCELLED（下一轮重新挂单，不跨轮滚单避免订单堆积无限）。

3) 定价：基于撮合后 撮合价（理论价）+ 行业公式（消除一字板核心）
   a. 撮合后的"理论本轮收盘价" newPrice = max(撮合均价, 上次 close)。若撮合无成交 → newPrice = 上轮 close。
   b. 取基本面因子：
      - 每股净利润 = initNetProfit*10000/totalShares（万→元换算）
      - 当前市盈率 P/E = industryPE（第 1 步更新后的有效值）
      - 公允价值 fairPrice = 每股净利润 × P/E = ROUND(initNetProfit*10000/totalShares*industryPE, 2)
      - 碳排偏离：carbonDev = (currentCarbon - industryAvgCarbon)/max(industryAvgCarbon,1)
        → carbonInfluence = -carbonDev * 0.15（碳排低于均值越多上涨，高于越多下跌）
      - 幸福度影响：happinessInfluence = (happiness - 50)/50 * 0.10（0~100 区间，超/低于50 ±10%）
   c. 干预限幅：
      - 理论最终 = fairPrice × (1 + carbonInfluence + happinessInfluence)
      - 再叠加成交偏离 0.3 权重（70% 基本面 + 30% 实际供需）：
        finalTheory = 0.7 × 理论最终 + 0.3 × 撮合后 newPrice
      - **±10% 涨跌幅硬限制**：finalClose = clamp(finalTheory, prevClose×0.9, prevClose×1.1)
      - 价格精度 = round(x, 2 位)

4) 生成 K 线 StockCandle：
   - round = Stock.round + 1；open = 上轮 close；high = max(撮合最高成交价, finalClose)；low = min(撮合最低成交价, finalClose)；close = finalClose；changePct = (close-open)/open × 100%（2 位小数）。
   - Stock.currentPrice = close；Stock.round = round。

5) 级联：若股票绑定了产业字段 → IndustryCalcEngine.recalculateForField(...)（因为公司现金/资本等字段随成交变动，反哺计算字段）。
6) 实时广播：broadcastResourceChange({competitionId, model:"Stock", ...}) + 每只股票发 `stock:new-candle {stockId, round}` → 前端 K 线图 ECharts setOption 追加新数据。
```

**权限分级**（`hasPermission` rank：manage ≥ edit ≥ view）：
- `stock:view`（默认所有 BASE_VIEW_PERMISSIONS 含此）：可读行情 / 买卖（读写自己的资金账户 + 自己的订单/持仓/账户本身属于自己，无需额外权限；但下单时校验 ownerId === 当前登录 userId 或 companyId 在 stockCompanyScopes 内 —— 具体看 Service 内 scope 校验）。
- `stock:edit`（低级管理）：管理范围内的公司（stockCompanyScopes JSON）的资金账户 / 自己的用户账户；可创建/修改/删除资金账户（限 bindFieldId 范围）、充值现金、创建/修改股票（限 companyId 匹配）。
- `stock:manage`（高级管理，SUPER_ADMIN_ONLY_PERMISSIONS 之一）：可见所有 / 增删股票 / 推进轮次（advanceRound）/ 配置 PE 联动 / 重置撮合。

**资金账户 bindFieldId 同步**：`StockFundsAccountService.applyDelta(accountId, deltaCash)` 事务内同时：
- cashBalance += deltaCash；
- 若 bindFieldId ≠ null → 调 CompanyFieldsService.upsertFieldValue(companyId, bindFieldId, currentValue+deltaCash)（乐观锁保护）。

### 5.4 HTTP 层 `api/request.ts`（Axios 实例）

```ts
const http = axios.create({
  baseURL: configStore.serverUrl + '/api',   // e.g. http://localhost:3000/api
  timeout: 15000,
  withCredentials: true,                     // CORS 带 cookie（Electron 场景：JWT 走 Header 不用 Cookie，但开启以备 websocket 鉴权共享）
});

// 请求拦截器
http.interceptors.request.use((config) => {
  const token = authStore.token;
  if (token) config.headers.Authorization = `Bearer ${token}`;
  config.headers['X-Request-Id'] = uuid();    // 服务端 AuditLog.requestId 链路追踪
  return config;
});

// 响应拦截器
http.interceptors.response.use(
  (response) => {
    const wrapped = response.data;             // { code, message, data }
    if (wrapped?.code !== 0) {
      ElMessage.error(wrapped.message || '业务错误');
      return Promise.reject(wrapped);
    }
    // 版本硬封锁检测（所有响应均可触发）
    if (response.headers['x-server-version']) versionStore.setServerVersion(response.headers['x-server-version']);
    return wrapped.data;
  },
  (error) => {
    if (error.response?.status === 401) {
      authStore.logout();                      // 清 token + 跳 /login
      ElMessage.error('登录已失效，请重新登录');
    } else if (error.response?.status === 409) {
      ElMessage.warning('数据已被他人修改，请刷新后重试');  // 乐观锁冲突
    } else if (error.response?.status === 429) {
      ElMessage.warning(error.response.data.message || '操作过于频繁');
    } else {
      const msg = error.response?.data?.message || error.message || '网络错误';
      ElMessage.error(msg);
    }
    return Promise.reject(error);
  }
);
```

### 5.5 IndexedDB 本地缓存 `api/cache.ts`

**Realm 隔离**：`realm = ${authStore.user.username}@${competitionId}` → DB 名 = `gipfel-cache-${realm}`。升级前"仅账号无 realm"的旧库（`gipfel-cache-${username}`）在 main.ts 启动时 `deleteOldAccountDbs()` 全部清空。

每比赛每账号一个独立 DB，彻底隔离跨比赛 / 跨账号缓存残留。

**表结构（Dexie）**：每张表对应一个 REST 资源实体：
```
materials(key=id, competitionId, updatedAt, data)
parts / products / techNodes / mapNodes / mapEdges / mapNodeTypes / pathTypes
infrastructures / fuels / vehicles / warehouses / productionLines
industryTypes / industryFields / companies / companyFieldValues
regions / consumerDemands / contractTypes / contracts
messages / messageRecipients
stocks / stockFundsAccounts / stockHoldings / stockOrders / stockCandles
lastSync(key=resource, syncedAt)
```
- `resourceChanged(events[])`（socket 推送过来）→ 逐条 upsert/delete 本地表 + 更新 lastSync。
- `getResourceList(resource)`：离线或弱网时优先本地表 → 在线时走 API 并后台刷新（stale-while-revalidate）。
- `sync.replay(afterSeq)`：断线重连成功后，取 `afterSeq = max(所有 lastSync 中最大 seq)` → 发 `sync:replay` 给网关 → 批量 apply 回来。

### 5.6 WebSocket 客户端 `realtime/socket.ts` + `realtime/resource-changed.ts` + `realtime/useResourceChanged.ts`

- socket.io-client 连接 `configStore.serverUrl`；`auth: { token: authStore.token }`（与 HTTP 同源同端口）。
- `connect → subscribe(competitionId)`：authStore.competitionId 切换时自动取消旧订阅 + 新订阅。
- 监听事件：
  - `resource:changed`：`{seq, model, action, id, data, competitionId}` → `resourceChanged.ts` dispatch 给 Pinia：① 更新 IndexedDB；② 若当前打开页面涉及该资源 → 触发 reactive 刷新（`useResourceChanged(['Contract'])` 组合式 hook 返回响应式 trigger）。
  - `message:new`：messageStore.unreadCount++ + 弹浮窗。
  - `sync:replay:result`：apply events。
  - `connect_error` / `disconnect`：顶栏红点提示 "连接中断，自动重连中"。
  - `auth:required`：强制改密 / 踢下线。
- `autoReconnect` 默认开（socket.io 内置指数退避，最大 10s）。

### 5.7 通用组件复用模式

- **`components/common/DataManager.vue`** —— 11 类基础数据的通用 CRUD 表格组件（props: type, columns, formSchema, permissions）。原料/零件/产品/地图类型/基建/燃料/载具/仓库/生产线均直接用该组件，只需在 `config/dataModules.ts` 中配置一份 schema（列、校验、表单字段、搜索字段）即可。

- **`components/contracts/...`** —— 合同编辑双模式：
  - SimpleContractTypeEditor.vue（简易模式：表单式，适合简单线性 effects）
  - ContractTypeGraphEditor.vue（可视化图：节点 + 连线 + vue-konva 画布）
  - 双向同步：任一模式编辑 → 更新 ContractType.effects/conditions/graph 三个 JSON；FormulaBuilder.vue 提供表达式输入（带字段/输入变量自动补全）；TrialCalculator.vue 提供合同试算（选 parties + 填 inputs → 本地走 engine 纯函数预览 effects 结果，无需执行）。

### 6.3 5 个范围字段（Scopes）机制

全部存在 `User` 模型，均为 JSON 字符串存公司 id 数组（null = 无限制；空数组 [] = 完全不允许）。

| 字段 | 配合的权限 Key | 生效场景 | 判定函数 / 位置 |
|------|---------------|----------|----------------|
| `companyScopes` | `contract:audit` | 审核合同时：该合同所有参与方公司 companyId 必须全部包含于 companyScopes（否则 ContractReviewGuard 403） | ContractReviewGuard.canActivate、contract.service.auditApprove |
| `viewCompanyScopes` | `company:view`（且不持 company:manage 或 data:region:edit） | 读取公司产业字段时：scopes 为空(null/[]) → 全部公司可见；scopes 非空 → 仅 companyId 在 scopes 内时可见"全部（含未发布 visible=false）"字段，范围外公司只读 visible=true 公开字段 | `canReadCompanyAllFields()`、`companyListScopes()`、CompanyController.findMany/findOne、CompanyFieldsService.getFieldsForCompany |
| `contractViewCompanyScopes` | `contract:view`（不影响更高权限 contract:audit/execute/manage） | 合同列表筛选：返回合同的 parties 中任一公司 id 在 scopes 内（null = 返回全部） | ContractService.findAll where 注入 |
| `stockCompanyScopes` | `stock:edit`（低级管理专属） | 资金账户管理：ownerType=COMPANY 的账户，其 companyId 须在 scopes 内；ownerType=USER 的账户 userId 匹配自己不受限。高级 stock:manage 不受此限制 | StockService CRUD 资金账户/股票 companyId 匹配 |

### 6.4 授予上限 `assertGrantAllowed` 校验规则（账户管理保存时）

```
actor 不是 SUPER_ADMIN → 直接拒绝（仅超管可改权限）。
target 是 SUPER_ADMIN → permissions 必须空数组（超管隐式全放，不落库）。
否则 targetRole ∈ {COMPETITION_ADMIN, PLAYER}：
  对每个待授予 perm：
    · SUPER_ADMIN_ONLY_PERMISSIONS（3 项：competition:manage / account:manage / stock:manage）→ 违规。
    · perm 不在 grantCeiling 内 →
        · 若 perm ∈ grantExtras → 提示"在扩展集中，需超管显式放开"。
        · 否则 → 提示"超出授予上限"。
所有 perm 通过 → allowed。
```

扩展集放开方式：超管在 `server/src/permissions/role-templates.ts` 中把目标 perm 从 `COMPETITION_ADMIN_EXTRAS` 数组**迁移**到 `grantCeiling` 数组中（编译/重启生效）。然后前端账户管理面板即可为该角色勾选此权限。

## 7. 错误码 / 异常处理规范

### 7.1 统一响应包装

```ts
interface ApiResponse<T> {
  code: number;    // 0=成功；非 0=错误
  message: string; // 中文可读消息，可直接 toast
  data: T | null;  // 成功 payload；错误时 null
}
```
实现：`ResponseInterceptor` 包裹所有非流式 handler 返回值；错误由 `HttpExceptionFilter` 输出同样结构。

### 7.2 常见 HTTP 状态码 & 错误场景

| 状态码 | 场景 | 典型 message |
|--------|------|-------------|
| 200 OK | 成功 | （无，code=0） |
| 201 Created | 创建成功 | （无，code=0） |
| 400 Bad Request | DTO 校验失败（class-validator whitelist / 必填 / 格式） | "名称不能为空（3-50 字符）"、"未定义字段 xxx 被禁止" |
| 400 | Prisma P2002 唯一冲突 | "名称 'xx' 已存在于当前比赛" |
| 400 | 循环依赖（科技树 / 计算字段图） | "添加依赖 xx→yy 产生循环" |
| 400 | 业务规则前置（合同条件 / IndustryField 定时器与计算字段互斥） | "合同前置条件 FIELD_COMPARE[B.cash_account >= 10000] 不满足" |
| 401 Unauthorized | JWT 缺失 / 过期 / 签名错 | "未登录或登录已过期" |
| 401 | tokenVersion 不匹配（被顶号） | "账号已在其他设备登录，请重新登录" |
| 401 | 用户名/密码错误 | "用户名或密码错误"（不含具体哪个错，防枚举） |
| 403 Forbidden | 路由 requiresPermission 未满足 | "无权限执行此操作" |
| 403 | 授予上限违规（assertGrantAllowed） | "权限 stock:manage 为超管专属，不可授予" / "权限 message:manage 在扩展集中，需超管显式放开" |
| 403 | 合同审核 companyScopes 越界 | "合同参与方包含审核范围外公司 123" |
| 403 | 比赛房间订阅越界（WS） | `subscribe:denied {reason:"无权订阅该比赛的实时广播"}` |
| 404 Not Found | 资源 id 不存在（或已被 OwnershipGuard 拦截判为越界 → 统一 404 避免泄露存在性） | "未找到" |
| 409 Conflict | 乐观锁 CompanyFieldValue.version 冲突 | "字段已被他人修改，请刷新后重试" |
| 422 Unprocessable Entity | 合同执行时 EngineConditions 校验失败 | （逐条列出失败条件详情） |
| 429 Too Many Requests | 登录限流 15 分钟锁定 | "登录尝试过于频繁，请 15 分钟后再试" |
| 500 Internal Server Error | 未捕获异常（堆栈已吞，仅 AuditLog 有原文） | "系统内部错误，请稍后重试"（5xx 一律不暴露细节） |

## 8. 审计 & 日志 & 可观测

### 8.1 AuditLog 表（R10 安全加固产物）

两张 kind：
- `kind=write`：**所有 Prisma 写操作**（create/update/upsert/delete/...）自动由 PrismaService.$allOperations middleware 写入。每条记录：
  - `operatorId + operatorName`（AsyncLocalStorage 中的登录用户，未登录时为 null）。
  - `action`：`<Model>:<op>` 如 `"CompanyFieldValue:updateMany"`。
  - `model`、`recordId`（主键 id 或批量 "N 行"）。
  - `competitionId`：从 data/where 路径推断（非比赛级资源如 User/AuditLog 本身为 null）。
  - `changes`：JSON diff（before vs after），passwordHash/token/secret 等敏感字段已被 sanitize 替换为 `[REDACTED]`。
  - `ip`、`requestId`（与 HTTP 头 X-Request-Id / socket handshake.transport 来源关联）。
- `kind=error`：**所有 5xx / 未捕获异常**由 HttpExceptionFilter 写入：
  - `statusCode`、`errorSummary`（通用中文摘要 + 异常类名，不含堆栈）。
  - 其它字段同上，便于按操作员/时间/requestId 溯源。

**查询方式**：
1. 开发：`npx prisma studio` → 打开 AuditLog 表。
2. 生产：`tools/logsreader/` → 双击 `run.bat` → 浏览器打开 http://localhost:3210 → 读取 server/logs 目录下的日志文件（SQLite AuditLog 读取需另行 DB 工具）。

### 8.2 Winston 文件日志

LOG_DIR（默认 `server/logs/`）下：
- `application-YYYY-MM-DD.log`：info 级以上，每条：
  ```
  [2026-03-18 15:42:33.123] [INFO] [LoggingInterceptor] GET /api/companies?page=1 status=200 latency=23ms operator=admin@1 requestId=abc123
  ```
- `error-YYYY-MM-DD.log`：仅 error 级（与上面重复写入 error，便于单独 grep）。
- 保留 20 天，超出自动删除；当日志超过 50MB 自动切分新文件 + gzip 压缩旧文件。

### 8.3 健康检查 & 版本接口（无鉴权）

- `GET /api/health`：空 body，200 表示 NestJS 进程存活（不查 DB）。
- `GET /api/version`：`{ version:"1.3.16" }`（读 package.json），响应头 `X-Server-Version: 1.3.16` 便于客户端拦截器在所有响应中顺便更新缓存。

## 9. API 设计通用规范

### 9.1 统一前缀 & 版本

所有 API 前缀 `/api`（`app.setGlobalPrefix('api')`）。目前无 API 版本规划，采用"无版本号、向后兼容"策略；破坏性变更通过新增路由 + 旧路由 deprecated 的方式演进。

### 9.2 分页列表规范

所有 GET 列表接口统一 query 参数：
```
?page=1        # 1-based，默认 1
?pageSize=20   # 每页条数，默认 20，最大 200
?keyword=      # 模糊搜索（按 name/displayName 等字段，不同模块略有差异）
?sortBy=       # 排序字段
?sortOrder=asc|desc
```

响应 payload：
```json
{
  "items": [ /* 实体数组 */ ],
  "total": 128,
  "page": 1,
  "pageSize": 20
}
```

### 9.3 关系加载策略

默认列表接口不 include relations；详情 GET `/:id` 按需 include 最常用 relation（如 company 含 fieldValues）。特殊深度关系通过独立子资源接口暴露（如 `/api/companies/:id/field-values`、`/api/tech-nodes/:id/graph` 返回含前置依赖的完整图）。

### 9.4 删除前影响确认

所有 DELETE 支持 `GET /api/<resource>/:id/delete-impact` → 返回 `{ relatedTables: [{name, count}] }`，前端删除确认对话框展示数量。删除操作不会静默级联不告知。

## 12. 故障排查速查

| 现象 | 根因 | 解决 |
|------|------|------|
| 客户端登录后立即弹窗"版本不一致，请联系管理员"且无法操作 | client/package.json 的 version 与 server 返回的 `/api/version` 不一致 | 执行 tools/updater/release-core.mjs 同步；或手动改两处 package.json 为同一值 → 重启 server + 重装 client |
| 客户端所有接口 401（刚登录就 401） | 服务端 JWT_SECRET 与签发时不同；或 tokenVersion 被并发登录取消 | 确认 server/.env JWT_SECRET 没变；登出再登录触发新 token；若是被顶号正常行为可忽略 |
| 合同执行 409 字段冲突 | 多个用户同时写同一公司同一产业字段 | 前端提示"已被他人修改，请刷新"后重试；可将高频写拆分为更多字段降低冲突率 |
| 地图背景图上传后看不到（Electron 控制台 CORP 报错） | CORS_ORIGIN 配置严格且服务端回 CORP=same-origin，但 Electron 渲染进程 origin 未命中白名单 | CORS_ORIGIN 留空（自动放行 file:// / app://）；或把 app://localhost 加入白名单 |
| 股票行情点"下一轮"后 K 线没变化 | 本轮没有挂单 → 撮合无成交 → newPrice=上轮 close → 若基本面因子也不变 → K 线看似平线（属正常） | 确认挂单存在；可在前端用 engine.spec.ts 同款参数调试 engine.ts |
| 登录失败 10 次后，正确密码也登不上（429） | 登录限流锁定 IP+用户名 15 分钟 | 等 15 分钟；或手动重启 server（限流器内存 Map 被清空）；生产环境可改为 Redis 持久化限流 |
| 产业字段值写入后"又自己变回去了" | 该字段是 `isCalculated=true`（计算字段），随被依赖字段写入立即被级联重算覆盖 | 编辑此字段所在的 IndustryField，修改 calcGraph 使其输出期望值；计算字段不可直接写（Service 已拦截，但批量导入可能绕过，建议通过 Service API） |
| 服务端启动报错 "JwtStrategy requires a secret or key" | JWT_SECRET 环境变量未设置 | cp .env.example .env，填入 JWT_SECRET |

## 13. 已知限制 & 后续演进方向（基于代码现状总结）

1. **SQLite 单实例**：单机读/写并发（100~500 级办赛方用户）够用，但无法水平扩展。若比赛规模达 10k+ 用户且需要多副本，可把 Prisma datasource 切换为 PostgreSQL（Schema 兼容，极少改动）。
2. **登录限流内存 Map**：单实例/重启清空。生产可换成 Redis（改造 login-throttle.ts）。
3. **WebSocket 广播 buffer（内存）**：重连补发仅保留最近 1000 条全局事件；更长断线（>1 小时）会走 IndexedDB 全量重新拉取，可接受。
4. **Electron 桌面客户端**：首次包体积较大（约 150MB 安装包）。若需 Web 端，把客户端的 Electron 主进程/preload 剥离、保留纯 Vue 3 + Vite 构建产物即可独立部署（WebSocket/HTTP 同源仍工作）。
5. **合同引擎 effects 仅 FIELD 效果**：所有业务动作收敛为"改产业字段"，设计刻意简化（降低复杂度 + 增强可追溯）。若未来需非字段效果（如发送消息/发股票/生成订单），可扩展 ContractEffect.type 新枚举 + 对应 Service 调用（在 ContractEngineService.execute 中 switch 扩展）。
6. **股票 PE 联动绑定 Region.overviewCards**：设计上为了让碳排/幸福度/PE 直接从"裁判已发布的区域总览卡片"取（公开一致），而不是原始内部字段。如需绑定任意 companyField 可扩展 ref 的结构（当前为 {region,cardId}，可扩展为 {companyId,industryFieldId}）。
